PHP2Shell: the identity angle everyone's missing

Two critical PHP vulnerabilities dropped today — CVE-2026-109618 and CVE-2026-109619, collectively "PHP2Shell." CVSS 9.2 each. Unauthenticated remote code execution in the PHP interpreter itself, affecting every version back to PHP 5.4. They sat undetected for over a decade until AI found them. Dutch government sites went offline. Pokémon went dark. It's a big deal, and the technical breakdowns are everywhere, so I won't rehash the longjmp() internals.

Here's the part nobody's leading with: Wiz demonstrated reading PHP worker memory — passwords, tokens, API keys — without achieving code execution.

Read that again. The attacker doesn't need a shell. A vulnerable PHP worker will hand over live session tokens and API keys to anyone who asks nicely. Every "is this RCE or just info disclosure" debate misses the point: in an identity context, memory disclosure IS the breach. A stolen session token doesn't need a shell — it needs a browser.

This is the conversation I'm having with customers this week:

Patch what you can, isolate what you can't. Fixes exist for PHP 8.2 through 8.5. If you're on 7.4–8.1, there are source backports but no official releases — which means you're compiling or upgrading, and "we'll get to it" isn't a plan. The NCSC said to consider taking systems offline until mitigated. That's not alarmism; that's what the math says when unauthenticated memory reads are in play.

Assume session exposure, not just server exposure. If you ran a vulnerable PHP version internet-facing in the last — well, decade — your incident response shouldn't stop at "did they get RCE." Rotate API keys. Invalidate sessions. The worker memory that was readable contained the keys to everything behind the login page.

Ask your vendors one question: "What PHP version runs your hosted service, and when did you patch?" If they can't answer in one sentence, that's your answer.

And the meta-story worth one paragraph: these bugs lived in the most-deployed server language on earth for 10+ years. Humans missed them. AI found them — Wiz used GPT models, another firm used Gemini. The auditing game just changed, permanently. If your threat model still assumes "someone would have noticed," update it.

Monday morning: inventory every internet-facing PHP host, patch 8.2+, isolate or offline the rest, rotate keys, invalidate sessions. The shell is the headline. The tokens are the story.
